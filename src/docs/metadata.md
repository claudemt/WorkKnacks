# 元数据提取

元数据提取是最程序化的一步。目标只有一个：**让 PDF 进入正确的母文献文件夹，并留下可靠的 `citation.bib`。**

## 最常用的流程

1. 把尚未整理的 PDF 放到项目根目录。
2. 点击 PDF 右侧的 **信息**。
3. 程序会优先从 PDF 中提取 DOI、arXiv 编号、ISBN、题名和作者，再查询学术数据库。
4. 检查识别结果，必要时手动改一两个字段，然后确认。
5. WorkKnacks 按 Zotero 风格命名建立文献文件夹，并把 PDF 和 `citation.bib` 放进去。

普通出版社 PDF 通常不需要 AI。对于双栏论文，程序会结合第一页版面、字号、摘要区和跨行 DOI，而不是简单把 PDF 文本流第一行当题名。

## 已经识别过的文献

再次点击 **信息** 会打开现有元数据，可以直接修改，也可以重新自动识别。文献文件夹上的 **编辑** 用于重新选择“哪一个 PDF 是主文献”，适合下载了新版、预印本或不同扫描版本后重新整理。

## 扫描书、老论文和异常 PDF

扫描件往往没有可用文本层，也可能没有 DOI。推荐顺序：

1. 先在 **信息** 中点 **自动识别**；
2. 常规数据库仍无结果时，再点 **AI复核**；
3. 程序会用 MinerU 读取前几页，提取题名、作者、ISBN/DOI 等线索，再与学术数据库候选对照；
4. AI 只给出简短推荐，最终仍由你确认。

这条辅助流程也适合老书、会议讲义、扫描论文和首页排版异常的文件。它不会代替人工确认，也不会把猜测直接写进资料库。

## 补充材料怎么放

补充材料属于母文章，不应该建立第二个“论文条目”。最稳妥的做法是：

1. 先识别主文献；
2. 把补充材料 PDF 手工复制到已经建立的母文献文件夹；
3. 对补充材料点 **信息 → 自动识别**；
4. 如果检测到它确实属于当前母文章，就直接作为附件登记，不创建重复文件夹。

因此一个文献目录通常是：

```text
<文献名>/
├── <主文献>.pdf
├── <补充材料>.pdf
├── citation.bib
├── parsed/
├── translations/
└── notes/
```

`.workknacks/` 只保存索引、AI 会话、缓存、备份和临时文件，不存需要你手工查找的论文产物。
